📋 STEP 1: READ THE DOCUMENTATION

   Primary Guide: docs/AGENT_EXECUTION_GUIDE.md
   - Complete problem diagnosis and response matrix
   - Safe command reference
   - Approval requirements
   - Verification procedures

   Quick Reference: docs/QUICK_REFERENCE.md
   - Fast lookup for common issues
   - Command cheat sheet

═══════════════════════════════════════════════════════════════════════

🔍 STEP 2: WHEN AN ISSUE IS DETECTED

   1. Run diagnostics FIRST:
      cd scripts
      ./quick_diagnostic.sh <SID> <INSTANCE_NUMBER>

   2. Review output and identify the problem

   3. Consult AGENT_EXECUTION_GUIDE.md for the correct response

   4. GET APPROVAL before running any healing script

═══════════════════════════════════════════════════════════════════════

🏥 STEP 3: RUNNING HEALING SCRIPTS

   ⚠️  CRITICAL: ALL healing scripts require explicit approval!

   Available healing scripts (in parent directory ../):
   - auto_db_userstoremanagement    [Risk: MEDIUM]
   - auto_db_metadata                [Risk: MEDIUM-HIGH]
   - auto_db_dbintegrations         [Risk: HIGH]
   - auto_db_eligibility            [Risk: MEDIUM]

   Example:
   cd ..
   ./auto_db_userstoremanagement <hostname>

═══════════════════════════════════════════════════════════════════════

✅ STEP 4: VERIFICATION (MANDATORY)

   After ANY healing operation:
   cd scripts
   ./verify_healing.sh <script_name> <SID> <INSTANCE>

   Example:
   ./verify_healing.sh auto_db_userstoremanagement ABC 00

═══════════════════════════════════════════════════════════════════════

📊 STEP 5: LOGGING

   ALL your actions must be logged to:
   logs/agent_actions_YYYYMMDD_HHMM.log

   Include:
   - Timestamp
   - Action taken
   - Results
   - Any errors or warnings

═══════════════════════════════════════════════════════════════════════

🚨 WHEN TO ESCALATE

   Escalate to human operator if:
   ☐ Database is DOWN
   ☐ Multiple healing attempts failed
   ☐ Unfamiliar error encountered
   ☐ Verification shows issues persist
   ☐ Any uncertainty about correct action
