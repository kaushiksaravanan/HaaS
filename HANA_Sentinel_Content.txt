1. Vision Statement 
An autonomous, explainable, policy-gated multi-agent system that transforms SAP HANA 
operations from reactive firefighting into proactive, self-healing infrastructure. Powered by 
Google Vertex AI, LangGraph orchestration, and a novel Risk Budget governance engine. 
 
2. Problem Statement and Market Context 
SAP HANA powers 87% of total global commerce through SAP's enterprise customer base. Yet 
the operational burden of maintaining HANA systems remains stubbornly manual. SAP Basis 
administrators perform daily routines that are well-defined, repetitive, and prime candidates for 
intelligent automation: checking system health, reviewing alerts, verifying backups, analyzing 
expensive SQL statements, monitoring capacity, and responding to security advisories. 
The problem breaks into four dimensions. First, reactive operations: teams discover issues from 
EarlyWatch Alert reports (delivered weekly as PDFs) or after users report problems, not before 
impact occurs. Second, fragmented tooling: SAP Landscape Management (mainstream 
maintenance ending December 2027), SAP Automation Pilot (primarily HANA Cloud, not on-
premise), and SAP Solution Manager (also end-of-life 2027) leave significant gaps. Third, 
knowledge silos: remediation expertise lives in the heads of senior Basis administrators, 
encoded in scattered SAP Notes and tribal knowledge rather than actionable automation. 
Fourth, compliance burden: SOX, GDPR, and now the EU AI Act demand auditable, explainable 
operations, making ad-hoc automation insufficient without governance frameworks. 
Existing solutions like Avantra provide ML-based anomaly detection but stop short of 
autonomous remediation. SAP's own Joule copilot focuses on conversational assistance rather 
than operational autonomy. No solution today combines detection, diagnosis, explainable 
remediation, policy-gated execution, and continuous learning in a unified multi-agent 
architecture for SAP HANA.

How HANA Sentinel Addresses January 2026 Patch Day 
The January 2026 Patch Day demonstrates exactly the problem HANA Sentinel solves. Within 
hours of SAP publishing security notes, the system performs the following automated workflow: 
• Browser-Use Agent navigates to SAP Support Portal and extracts the full list of security 
notes, CVE identifiers, affected components, and CVSS scores from the Patch Day 
bulletin page. 
• RAG Agent ingests the extracted security notes into the Vertex AI knowledge corpus, 
making them immediately queryable by all operational agents. 
• Security Agent cross-references affected components (especially SAP Note 3691059 for 
HANA privilege escalation CVE-2026-0492) against the managed HANA landscape, 
generating an Action Certificate for each applicable patch. 
• For CVE-2026-0492 (HANA Privilege Escalation, CVSS 8.8), the Security Agent checks 
current HANA version, identifies exposed authentication boundaries, and generates an 
X-Fix report recommending immediate patching with blast radius analysis. 
• Each remediation proposal flows through the Policy Engine and Risk Budget before 
reaching the Basis team for approval, with the X-Fix report providing full context for 
informed decision-making.

Why LangGraph as the Orchestration Framework 
LangGraph (GA May 2025, MIT-licensed, 400+ production deployments at companies like 
LinkedIn, Uber, and Elastic) models AI workflows as directed cyclic graphs with explicit state 
machines. This is critical for SAP operations because HANA remediation workflows are 
inherently stateful, branching, and require checkpointing. 
• Reducer-driven state schemas using Python Annotated types prevent data loss in multi-
agent environments 
• Checkpointing via PostgresSaver enables time-travel debugging and fault-tolerant 
execution 
• interrupt() function provides native human-in-the-loop support, pausing execution at 
policy gates 
• Sub-graph composition allows each specialized agent to be its own LangGraph graph, 
composed into the supervisor's orchestration graph 
• Native Vertex AI integration via agent_engines.LanggraphAgent class for managed 
deployment on Google Cloud

Policy Engine (OPA/Rego) 
The control plane uses Open Policy Agent (OPA), a CNCF-graduated project with sub-
millisecond policy evaluation, as its decision engine. Policies are written in Rego and enforced 
before every agent action. The engine evaluates risk tiers (low/medium/high/critical), checks 
budget sufficiency, enforces maintenance windows for critical actions, and prevents agents from 
approving their own actions (separation of duties). 
 
  
5. Agent Risk Budget (Novel Governance Mechanism) 
HANA Sentinel introduces the Agent Risk Budget, adapted from Google's SRE error budget 
model. Just as SRE teams have an error budget (1 minus SLO) that permits controlled risk-
taking while protecting reliability, each HANA Sentinel deployment operates with a risk budget 
that governs cumulative autonomous action. 
Every agent action consumes risk points from a shared budget based on a 5x5 risk matrix 
(Likelihood x Impact). The budget replenishes over a rolling 24-hour window, with trust 
multipliers rewarding successful operations and penalty mechanisms reducing capacity after 
incidents.

6. Action Certificates (Signed Pre-Approved 
Remediation Plans) 
Every non-trivial agent action in HANA Sentinel requires an Action Certificate, a digitally signed 
document that fully describes what will be done, why, what could go wrong, and how to undo it. 
This concept draws from Terraform's plan/apply model, AWS Systems Manager runbooks, and 
Columbia University's research on Autonomy Certificates (Feng et al., 2025). 
Action Certificates serve three purposes: they enforce pre-execution review, they create an 
immutable audit record for compliance, and they enable the replay capability by fully capturing 
decision context.

7. Specialized Agent Specifications 
Each agent follows the single-responsibility principle: one agent, one domain, clear input/output 
contracts. Agents communicate through structured intents over Google Cloud Pub/Sub (not 
natural language) to reduce hallucination risk and latency. 
 
7.1 Health Monitor Agent 
Continuous monitoring of SAP HANA system health via M_* monitoring views. Generates 
structured health assessments every 60 seconds covering services, memory, disk, CPU, alerts, 
and system replication. 
Key HANA interfaces: M_SERVICES, M_HOST_RESOURCE_UTILIZATION, 
M_SERVICE_MEMORY, STATISTICS_CURRENT_ALERTS, M_DISK_USAGE, 
M_SYSTEM_REPLICATION, M_LOAD_HISTORY_SERVICE 
 
7.2 Backup Agent 
Manages the entire backup lifecycle: scheduling, execution, verification, catalog housekeeping, 
and failure recovery. Interfaces directly with HANA via hdbcli for BACKUP DATA commands 
and M_BACKUP_CATALOG monitoring. 
Risk levels: Read catalog = 1 point; trigger differential = 6 points; trigger full = 6 points; catalog 
delete = 8 points. 
 
7.3 Recovery Agent 
Detects service failures and executes recovery procedures, from simple service restarts to 
system replication takeover. Monitors M_SERVICES for status changes and executes recovery 
via sapcontrol (OS-level commands via SSH) and SQL ALTER SYSTEM START SERVICE. 
 
7.4 SQL Tuning Agent 
Identifies expensive SQL statements, analyzes execution plans, and recommends or executes 
optimizations. Queries M_SQL_PLAN_CACHE, M_EXPENSIVE_STATEMENTS, and 
M_ACTIVE_STATEMENTS. Before recommending tuning actions, the SQL Tuning Agent 
queries the RAG Agent with the problematic SQL pattern to retrieve relevant SAP Notes and 
known performance issues. 
 
7.5 Capacity Agent 
Tracks disk, memory, and table growth trends. Predicts capacity thresholds and recommends 
actions before exhaustion. Integrates with the global.ini configuration management workflow 
(see Section 8) to ensure backup and data volume paths are correctly configured. 
 
7.6 Security Agent 
Continuous security posture assessment covering privilege auditing, password policy 
compliance, encryption verification, audit policy checks, and SAP Security Patch Day 
vulnerability assessment. Queries EFFECTIVE_PRIVILEGES, M_PASSWORD_POLICY, 
M_ENCRYPTION_OVERVIEW, and AUDIT_POLICIES. 
For the January 2026 Patch Day specifically, the Security Agent would flag CVE-2026-0492 
(HANA Privilege Escalation, CVSS 8.8) as directly affecting the managed HANA instance and 
generate an Action Certificate recommending immediate assessment and patching.

8. Configuration Agent: global.ini Management 
A critical operational requirement for HANA Express and production HANA systems is ensuring 
the global.ini configuration file contains correct backup and volume path entries. HANA 
Sentinel's Capacity Agent and Backup Agent jointly manage this configuration as part of their 
initialization and continuous compliance checks. 
 
Target Configuration 
File path: /usr/sap/HXE/SYS/global/hdb/custom/config/global.ini 
 
The agents verify that the following entries exist under the [persistence] section: 
[persistence] 
basepath_databackup = /hdb/HXE/backup/data 
basepath_logbackup = /hdb/HXE/backup/log 
basepath_datavolumes = /hdb/HXE/data 
basepath_logvolumes = /hdb/HXE/log 
 
Agent Workflow for global.ini Compliance 
Step 1 (Detection): On startup and every 15 minutes, the Capacity Agent reads the global.ini file 
via SSH and parses the [persistence] section. 
Step 2 (Validation): The agent checks whether all four required entries (basepath_databackup, 
basepath_logbackup, basepath_datavolumes, basepath_logvolumes) are present with correct 
values. 
Step 3 (Remediation): If any entries are missing, the agent generates an Action Certificate 
describing the exact changes needed. Since this is a parameter change (risk score: 6), it flows 
through the Policy Engine for approval in accordance with the current governance mode. 
Step 4 (Execution): Upon approval, the agent appends the missing entries to global.ini using 
sed or direct file manipulation via SSH. It then verifies the changes by re-reading the file. 
Step 5 (Verification): The agent queries M_INIFILE_CONTENTS via SQL to confirm HANA has 
picked up the configuration changes. If HANA requires a restart to apply changes, the agent 
escalates to the Recovery Agent with appropriate risk scoring. 
 
Implementation Detail 
# Agent checks global.ini via SSH 
def check_global_ini(ssh_client): 
    ini_path = '/usr/sap/HXE/SYS/global/hdb/custom/config/global.ini' 
    required_entries = { 
        'basepath_databackup': '/hdb/HXE/backup/data', 
        'basepath_logbackup': '/hdb/HXE/backup/log', 
        'basepath_datavolumes': '/hdb/HXE/data', 
        'basepath_logvolumes': '/hdb/HXE/log' 
    } 
     
    stdin, stdout, stderr = ssh_client.exec_command(f'cat {ini_path}') 
    content = stdout.read().decode() 
     
    missing = {} 
    for key, value in required_entries.items(): 
        if f'{key} = {value}' not in content: 
            missing[key] = value 
     
    if missing: 
        return generate_action_certificate( 
            action_type='config_update', 
            target='global.ini [persistence]', 
            changes=missing, 
            risk_score=6, 
            rollback='Remove added entries from global.ini' 
        ) 
    return None  # All entries present 
 
The basepath_logbackup entry is particularly critical because it enables automatic log backups, 
which are essential for point-in-time recovery. Without this entry, HANA's log area can fill up and 
block all transactions. The Backup Agent depends on this path being correctly configured before 
it can execute any log backup operations. 
 
  
9. RAG Agent: Vertex AI-Powered Knowledge Engine 
The RAG Agent serves dual roles: it grounds operational agents' decisions in SAP 
documentation (ensuring recommendations are based on official SAP Notes, not LLM 
hallucinations), and it powers a user-facing support assistant that Basis administrators can 
query in natural language. 
 
Ingestion Pipeline 
• SAP EWA Reports (PDF) parsed via Document AI Layout Parser 
• SAP Notes (HTML/PDF) from SAP Support Portal 
• HANA Administration Guides (PDF) 
• SAP KBAs (Knowledge Base Articles) 
• SAP Security Patch Day bulletins (HTML, extracted by Browser-Use Agent) 
• Internal runbooks and operational procedures 
 
Vertex AI RAG Engine Configuration 
from vertexai import rag 
import vertexai 
 
vertexai.init(project='hana-sentinel', location='us-central1') 
 
sap_corpus = rag.create_corpus( 
    display_name='sap-hana-knowledge-base', 
    description='SAP Notes, EWA reports, HANA admin guides, Patch Day bulletins' 
) 
 
rag.import_files( 
    corpus_name=sap_corpus.name, 
    paths=['gs://hana-sentinel-docs/sap-notes/', 
           'gs://hana-sentinel-docs/ewa-reports/', 
           'gs://hana-sentinel-docs/hana-admin-guides/', 
           'gs://hana-sentinel-docs/patch-day-bulletins/'], 
    transformation_config=rag.TransformationConfig( 
        rag.ChunkingConfig(chunk_size=512, chunk_overlap=100) 
    ), 
    max_embedding_requests_per_min=900 
) 
 
Embedding model: gemini-embedding-001 (3072 dimensions, 8,192 token input limit). Hybrid 
search (semantic + keyword) is critical because keyword search catches exact SAP Note 
numbers (e.g., SAP Note 2222200) and error codes, while semantic search handles conceptual 
queries. 
 
Dual-Role Operation 
Role 1 (Agent Grounding): When operational agents need to make decisions, they query the 
RAG Agent to retrieve relevant documentation. The SQL Tuning Agent, for example, queries the 
RAG corpus with a problematic SQL pattern before recommending optimization. The response 
includes citations to specific SAP Notes and admin guide sections, which are embedded into the 
Action Certificate's rag_sources field. 
 
Role 2 (Support Assistant): Basis administrators can query the RAG Agent directly via the 
HANA Sentinel UI or CLI. Example: 'How do I reduce memory pressure in HANA columnstore?' 
returns an answer grounded in SAP Note 2222200 and the HANA Administration Guide Chapter 
12, with confidence scores and source citations. 
 
  
10. Browser-Use Agent: SAP Web Interface 
Automation 
The Browser-Use Agent leverages the browser-use Python framework (v0.10.1) to automate 
interactions with SAP web interfaces that lack programmatic APIs. Built on Chrome DevTools 
Protocol (CDP), it uses a hybrid DOM analysis + visual understanding approach where an LLM 
determines actions based on both the serialized DOM tree and screenshots, making it resilient 
to SAP Fiori's notoriously dynamic element IDs. 
 
Key Use Cases 
• SAP Security Patch Day monitoring: Navigate to support.sap.com, extract security note 
lists, CVE identifiers, CVSS scores, and affected components from the monthly Patch 
Day bulletin. 
• HANA Cockpit data extraction: Navigate to System Overview tiles, extract health 
dashboards, capture KPI visualizations as audit screenshots. 
• EWA report retrieval: Access Solution Manager, navigate to EarlyWatch Alert 
Management, extract the latest report's Service Summary, Performance, and Security 
sections. 
• SAP Note detail extraction: For each relevant security note (like 3691059 for HANA 
privilege escalation), extract full remediation steps, affected versions, and workaround 
instructions. 
• Configuration operations: Perform administrative tasks in HANA Cockpit that are not 
exposed via SQL.

12. Replayable Incidents and Continuous Learning 
HANA Sentinel records every incident with full system state, event streams, and agent decision 
traces, enabling sandbox replay for continuous improvement. This is the system's learning 
flywheel: incidents become training data, what-if scenarios validate policy changes, and 
historical pattern matching (via vector similarity search on pgvector embeddings) accelerates 
future diagnosis.

14. REST API Contracts

18. Innovation Highlights for Hackathon Judges 
 
Innovation 1: Agent Risk Budgets. First application of SRE error budget principles to 
autonomous AI agent governance. Creates a quantitative trust framework that enables 
graduated autonomy without binary 'fully manual' or 'fully automated' choices. No existing SAP 
automation tool implements this. 
 
Innovation 2: Action Certificates. Digitally signed, pre-validated remediation plans with 
preconditions, postconditions, blast radius analysis, and automatic rollback triggers. Bridges the 
gap between infrastructure-as-code approval patterns (Terraform plan/apply) and AI agent 
autonomy. 
 
Innovation 3: Explainable Remediation (X-Fix). Every automated action generates a 
structured explanation grounded in observable system state (not LLM narrative), mapping 
directly to ITIL RFC fields. This makes AI actions auditable for SOX, GDPR, and EU AI Act 
compliance. 
 
Innovation 4: Incident Replay as a Learning Flywheel. Recorded incidents become training 
data for what-if analysis, enabling continuous agent improvement. Combined with vector-
similarity search, new incidents are matched to historical patterns for accelerated diagnosis. 
 
Innovation 5: Browser-Use + SAP Fiori. Novel application of LLM-driven browser automation 
to SAP's web interfaces. The hybrid DOM + vision approach handles Fiori's dynamic IDs 
naturally, eliminating brittle selector-based automation. Applied to SAP Security Patch Day 
monitoring for real-time vulnerability assessment. 
 
Innovation 6: Chaos Engineering for SAP. Built-in failure simulation framework validates 
agent responses before production deployment. Very few teams apply chaos engineering 
principles to SAP infrastructure. 
 
Google + SAP Partnership Alignment 
• Uses Agent2Agent (A2A) protocol patterns (SAP is a founding contributor) 
• Deploys on Vertex AI Agent Engine with native LangGraph support 
• Leverages Gemini models available via SAP BTP Generative AI Hub 
• Demonstrates zero-copy data patterns mirroring SAP BDC Connect for BigQuery 
• Implements OpenTelemetry (Google-championed standard) for full observability 
• Runs on GCP infrastructure (n2-standard-8, Cloud SQL, Cloud Run, Pub/Sub)
